# 嵌入式 Linux 整体认识

> 早期学习已了解系统全貌，随后先深入用户态系统编程。驱动部分是本次补充的概念速览，内核模块、驱动编写与开发板实验的完成情况仍待核验。

## 系统全景

~~~text
开发主机（Host）── 编译、构建、部署与调试 ──→ 目标设备（Target）

用户空间      C/C++ 应用、脚本、服务、界面
    ↕         库接口与系统调用
Linux 内核    调度、虚拟内存、VFS、网络、驱动
    ↕         设备总线、寄存器、中断、DMA
硬件          CPU/SoC、RAM、Flash、外设
~~~

从应用往下看，内核管理资源并提供文件、网络与设备访问接口，驱动负责设备适配。应用通常通过系统调用或库接口访问这些能力，由内核执行需要特权的操作。从设备上电往后看，启动链先使内核运行，再让用户空间的服务和业务程序启动。

## 裸机、RTOS 与嵌入式 Linux

| 概念 | 主要作用 |
| --- | --- |
| 裸机 | 程序直接管理硬件，常用主循环和中断组织任务。 |
| RTOS | 提供任务调度、同步和通信，强调响应时间的可预测性。 |
| Linux 内核 | 提供调度、内存管理、文件系统、网络协议栈和驱动等机制。 |
| Linux 发行版 | 将内核、库、软件包和工具组织成可用系统，例如 Ubuntu。 |
| 嵌入式 Linux | 为具体设备选配 Linux 内核与用户空间，重点是硬件适配、启动、存储和长期运行。 |

普通 Linux 无法保证硬实时。`PREEMPT_RT` 可减少部分调度延迟，仍需在目标硬件、驱动和代表性负载下核验最坏响应时间。严格时限的控制也可交给 MCU、FPGA 或专用硬件，由 Linux 处理网络和业务逻辑。

## 从上电到应用

~~~text
BootROM → 可选的 SPL/FSBL → 引导程序（如 U-Boot） → Linux 内核
                                                     ↓
                                        根文件系统 → PID 1 → 服务和应用
~~~

| 阶段 | 主要工作 |
| --- | --- |
| BootROM | 芯片内置启动代码，根据启动配置从相应介质寻找下一阶段。 |
| SPL／FSBL | 视平台完成早期初始化，例如准备 DRAM，再加载后续引导程序。 |
| Bootloader | 将内核映像和必要启动数据放到内核可访问的位置，传递参数并交出控制权。 |
| Linux 内核 | 初始化内存、调度、驱动等子系统，建立可用的根文件系统，再进入用户空间。 |
| RootFS 与 init | 根文件系统提供库、配置和程序。PID 1 的 init（如 systemd 或 BusyBox init）负责启动服务。 |

**内核映像**是被加载执行的内核。**DTB** 是编译后的硬件描述，在需要设备树的平台通常随启动流程交给内核。**RootFS** 是用户空间看到的根目录树，具体启动流程可能先使用 initramfs，再切换到最终根文件系统。

## 内核职责与用户空间

| 内核能力 | 应用能看到什么 |
| --- | --- |
| 进程与调度 | 执行流共享 CPU，可创建进程并等待其退出。 |
| 虚拟内存与 MMU | 进程获得受保护的虚拟地址空间，能建立内存映射。 |
| VFS 与文件系统 | 不同文件系统提供统一的打开、读写等接口。 |
| 网络协议栈 | 应用通过套接字使用 TCP、UDP 等协议。 |
| 驱动、中断与同步 | 应用可读取设备数据或等待事件，内核负责硬件交互和并发协调。 |

用户态与内核态具有不同的执行权限。用户程序通过系统调用请求内核服务。标准库可能封装系统调用，也可能在用户态完成工作，例如缓冲输出不一定立即触发写入。

## 文件系统

| 路径 | 用途 |
| --- | --- |
| `/bin`、`/usr/bin`、`/usr` | 可执行程序及共享资源，具体目录布局因系统而异。 |
| `/lib`、`/usr/lib` | 运行库等支持文件。 |
| `/etc`、`/var` | 系统配置，及日志、缓存等可变数据。 |
| `/dev` | 设备节点，例如串口或块设备。 |
| `/proc`、`/sys` | 分别提供进程与内核状态，以及设备模型和内核对象属性的虚拟接口。 |
| `/home`、`/tmp` | 用户目录与临时文件，清理策略由系统配置决定。 |

「一切皆文件」概括了部分接口的统一性。普通文件、管道、套接字和某些设备都可以用文件描述符访问，支持的操作取决于对象。例如普通文件通常可定位，管道不支持移动偏移。设备节点常见的访问路径是 `open` 获得 FD，再通过 `read`、`write` 或设备支持的 `ioctl`、`mmap` 与内核子系统交互，最后用 `close` 释放 FD。

## 设备树与驱动速览

### 设备树描述硬件

设备树可描述设备地址、时钟、中断、GPIO 连接和总线关系。**DTS** 是源码，**DTSI** 是可复用的包含文件，**DTB** 是编译产物。许多 ARM 和 RISC-V 平台使用设备树。节点的 `compatible` 可用于匹配驱动，绑定仍取决于设备状态、驱动以及资源初始化。设备树描述板上有哪些设备及资源关系，驱动决定如何使用这些资源。

### 驱动与设备子系统

驱动通常在内核中初始化设备、管理资源与缓冲、处理事件和错误，并通过内核子系统向上提供接口。也有设备使用用户空间驱动或专门框架。

| 类型 | 典型用途或接口 |
| --- | --- |
| 字符设备 | 字节流和控制操作，常见设备节点及 `file_operations`。 |
| 块设备 | 按块访问存储，通过块层供文件系统等使用。 |
| 网络设备 | 通过网络子系统收发数据包，用户程序通常使用套接字。 |
| Platform Driver | 常见于 SoC 片上、缺少自动枚举机制的外设，可结合设备树匹配。 |
| 总线和专门子系统 | SPI、I²C、USB、PCIe 等有各自的设备模型。GPIO、PWM、IIO、V4L2、ALSA 提供面向特定外设的框架，UART 常通过串口相关子系统管理。 |

驱动可编进内核，也可按配置编成可加载的 `.ko` 模块。`probe` 和 `remove` 是部分设备模型中常见的绑定与解绑回调。`ioctl` 用于部分设备控制，`mmap` 可在接口支持时把缓冲或文件映射到用户进程。接口细节见[文件接口延伸](./09-io-extensions.md)。

### 外设、IRQ 与 DMA

GPIO 处理通用数字电平，UART／I²C／SPI 用于不同拓扑和用途的串行通信，定时器与 PWM 用于定时或波形输出，ADC 负责采样，可由 IIO 等框架提供访问接口。IRQ 让设备通知 CPU，需遵守处理中断时的上下文约束。DMA 可在设备与内存等位置之间搬运数据，减少 CPU 逐项复制，仍需管理缓冲、缓存一致性及同步。

采集设备可用这条路径理解分工。具体产品可能使用 IIO 缓冲、专用设备节点或其他框架。

~~~text
传感器／ADC／FPGA → 总线、IRQ 与 DMA → 驱动和内核数据接口
                   → 用户程序处理、存盘或发送 → 服务管理、日志和监控
~~~

## Host 与 Target

Host 是写代码和构建的开发环境，例如 Windows 上的 Ubuntu 虚拟机。Target 是最终运行程序的设备，例如 ARM 开发板。在 Ubuntu x86-64 构建并运行是本机编译，从 x86-64 生成 ARM 程序是交叉编译。交叉构建还需匹配目标 ABI、动态链接器及依赖库。

GCC／Clang 编译，Make／CMake 组织构建，GDB 调试，Git 管理版本，SSH／SCP 可用于远程访问和传输。在 Ubuntu 上可先练习系统编程，QEMU 可用于观察其他架构和启动过程，真实外设与时序仍需开发板验证。相关操作见[终端命令](./02-terminal-commands.md)和[Linux C 开发与编译调试](./03-development-toolchain.md)。

## RootFS 与系统构建

| 名称 | 用途 |
| --- | --- |
| RootFS | 用户空间运行所需的目录树、程序、配置和库。 |
| BusyBox | 把常用 Unix 工具集中到紧凑程序，可用于精简系统。 |
| Buildroot | 可生成交叉工具链、根文件系统、内核和引导组件的构建系统。 |
| Yocto Project | 用构建工具、配方和层组织可定制的嵌入式 Linux 系统镜像。 |

可先在虚拟环境中串起内核与精简 RootFS，再了解产品所需的构建流程和板级适配。

## 用户态专题入口

| 主题 | 先理解什么 | 继续阅读 |
| --- | --- | --- |
| 文件与设备 I/O | FD 指向打开的 I/O 对象，读写与定位的语义取决于对象。 | [文件描述符与文件 I/O](./04-file-descriptors-and-io.md)、[文件偏移与 lseek](./05-lseek-and-errors.md) |
| I/O 就绪 | 非阻塞调用在暂不可用时可返回 `EAGAIN`，多路复用可等待多个 FD。 | [阻塞与非阻塞 I/O](./06-blocking-and-nonblocking.md)、[select、poll 与 epoll](./07-select-poll-epoll.md) |
| 进程 | `fork` 创建子进程，`exec` 替换程序映像，`waitpid` 等待并回收子进程。 | [进程基础](./08-process-introduction.md) |
| 线程与 IPC | 线程共享所属进程的地址空间。管道、共享内存、消息队列、信号和套接字是进程间协作的不同机制，锁、条件变量和信号量用于协调并发。 | 后续专题 |

## 调试与工程化

排查时先确定问题出在启动、硬件、内核接口、驱动还是应用。启动问题可看串口控制台和 `dmesg`，服务及日志可按系统配置用 `journalctl`，用户态可用 GDB、日志和 `strace`，运行状态可看 `top`、`ps`，性能分析再按环境选择 `perf`。

- **服务与诊断**　用 init 或服务管理器维护自启动和进程生命周期。日志记录关键状态，并考虑轮转与 Flash 写入寿命。
- **可靠运行**　看门狗帮助系统从失去响应的状态恢复。存储设计要考虑掉电一致性、可写分区与介质寿命。
- **交付和维护**　升级需考虑完整性校验、失败回滚和断电恢复。远程维护需限制权限和保护密钥，设备交互可按需求采用 CLI、Web 或图形界面。

## 小结与自测

沿着两条线复习。开机线从 BootROM 到内核、RootFS 和服务，数据线从外设经驱动与内核接口到应用。用户态可依次复习进程、线程与同步、IPC 和网络。系统方向可按交叉编译、QEMU、内核与 RootFS、构建系统推进，之后再结合硬件深入设备树、驱动和 IRQ／DMA。

1. 发行版、内核、RTOS 和裸机在系统职责上有什么区别？
2. 从 BootROM 到 PID 1，每一阶段交付了什么？DTB 在哪一段发挥作用？
3. `/dev`、`/proc`、`/sys` 分别暴露什么？字符设备、块设备和网卡为何采用不同的访问路径？
4. 用一个 ADC 采集例子说明驱动、IRQ、DMA 和用户程序如何协作。
5. 从 Ubuntu x86-64 编译给 ARM 开发板时，谁是 Host、谁是 Target？架构、ABI、动态链接器和库要怎样匹配？
6. BusyBox、RootFS、Buildroot 与 Yocto 各解决什么问题？应用能启动但采不到数据时，应该从哪些层检查？
